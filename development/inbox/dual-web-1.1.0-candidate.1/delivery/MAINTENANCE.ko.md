# 수정·적용·되돌리기

## 기존 저장소에 붙이는 범위

이 패키지의 `delivery/`만 저장소 최상위에 추가하면 된다. 기준 커밋에는 이 이름의 폴더가 없었음을 저장소 트리에서 확인했다. 나중에 같은 이름의 폴더가 생겼다면 무조건 덮어쓰지 말고 먼저 비교한다. 원래 파일을 수정하는 패치는 이번 패키지에 포함하지 않는다.

현재 GitHub 원격 저장소에 커밋·푸시·배포한 것은 아니다. 포함된 `delivery/`는 선택적으로 추가할 수 있는 실제 코드다. 빌드 결과를 기존 웹 전체에 덮어씌우는 도구도 아니다.

## 수정 위치

| 바꾸려는 것 | 위치 | 확인할 검사 |
|---|---|---|
| 자료 선택·역할·파일 크기·형식 | `dualweb/core.py` | 원문 보존, 역할 충돌, 미선언 파일, 크기 제한 |
| 묶음·안내 형식 | `dualweb/core.py`의 `render` | 결정적 출력, 내용 변경 식별자, 보조 문서만 바뀐 경우 |
| HTTP 응답·캐시·경로 정책 | `dualweb/server.py` | 실제 GET/HEAD/304/412, HTML 차단 중 AI 접근, 우회 경로 |
| 명령 인터페이스 | `dualweb/cli.py` | 잘못된 입력의 종료 코드, 기존 출력 보존 |
| 비교 측정 | `tools/measure.py` | 비교하는 원문 집합의 동등성, 본문 바이트와 요청 수 구분 |

모델·API·외부 호스팅 서비스 의존성을 추가하지 않은 작은 구현이다. 새로운 근거 형식을 지원하려면 원문과 역할 보존 검사를 먼저 추가한다. 공개 표면 범위를 넓힐 때는 새 파일이 정말 공개 대상인지 별도로 확인한다.

## 이번에 의도적으로 하지 않은 것

웹사이트 전체 재작성, 자동 DB→HTML 동기화, 에이전트 신원 인증, 결제 실행, 사이트별 봇 판별, WAF 설정 변경, 운영 CDN 배포, 고빈도 푸시 알림은 구현하지 않았다. 이는 기능을 삭제했다는 뜻이 아니라 기존 코어에 없던 다른 책임을 이번 개선에 억지로 넣지 않았다는 뜻이다.

원본 근거와 사람이 보는 화면의 의미가 일치하는지를 자동으로 증명하지 않는다. 날짜·서명·해시·스키마 통과 중 어느 것도 현실 사실 검증으로 승격하지 않는다. 기존 `canon`과 근거의 확인·갱신 책임은 발행자에게 남는다.

## 되돌리기

운영 적용 전이라면 원래 저장소 파일은 변경되지 않는다. 새 도구를 사용하지 않는 것으로 원래 방식으로 돌아갈 수 있다. 새로 만든 배포 폴더와 코드의 정리는 본인이 확인한 뒤 수행한다. 자동 삭제 명령은 제공하지 않는다.

운영 반영 후라면 호스팅의 이전 배포본으로 되돌리는 절차를 사용한다. 이미 외부로 전달되거나 캐시된 공개 자료까지 회수할 수 있다는 보장은 없다. 정보 철회가 중요한 자료는 짧은 유효기간·정정 경로·운영 정책을 별도로 설계해야 한다.

## 재검사

```sh
python -m unittest discover -s delivery/tests -v
python delivery/tools/verify.py
python delivery/tools/measure.py
```

새 실행 결과는 동봉된 과거 검사 기록을 덮어쓰기보다 별도 판본으로 남기는 편이 비교하기 쉽다. 검사 코드 수정 뒤에는 `reports/validation.json`에 있는 과거 코드 해시와 현재 코드를 같은 판본이라고 취급하지 않는다.
